# Submission Checklist

> **Deadline**: September 27, 2026 — 10:00 PM Indochina Time
> Submit via: https://lablab.ai/ai-hackathons/ibm-bob-2-hackathon

Tick every box before hitting Submit. A missing item can disqualify your project.

---

## ✅ PRE-HACKATHON (Complete Before Sep 25)

- [ ] Registered on lablab.ai before Sep 24, 10PM CEST
- [ ] Received IBM Bob hackathon invite email (check Spam/Junk)
- [ ] Installed Bob IDE (v2.0.2 or later)
- [ ] Signed into Bob IDE with IBMid using hackathon registration email
- [ ] Switched Bob IDE to **ibm-coding-challenge-uat (region: us-east)** account
  - Settings → General → Switch team → ibm-coding-challenge-uat (region: us-east)
- [ ] Joined or formed a team (via lablab.ai dashboard or Discord)
- [ ] Read the official hackathon guide fully
- [ ] Problem statement drafted in `planning/PROBLEM_STATEMENT.md`
- [ ] GitHub repo created (public) — optionally using the IBM Hackathon Template
- [ ] `.gitignore` and `.bobignore` in place to prevent credential leaks

---

## ✅ DURING BUILD (Running Checklist)

- [ ] IBM Bob IDE used as the **core** tool (not just a helper)
- [ ] Agent mode used for at least one autonomous multi-step task
- [ ] Subagents used for at least one parallel task
- [ ] Bob task session screenshots captured and saved to `bob_sessions/` as work progresses
  - Screenshot naming: `teamname_task##_short_description_summary.png`
- [ ] NO IBM Cloud credentials or API keys committed to the repo
- [ ] Bobcoin budget monitored in Bob IDE Settings

---

## ✅ SUBMISSION FIELDS (lablab.ai Platform)

### 📋 Basic Information
- [ ] **Project Title** — clear, memorable name
- [ ] **Short Description** — 1–2 sentences
- [ ] **Long Description** — Problem & Solution Statement (max 500 words)
  - Refer to `planning/PROBLEM_STATEMENT.md` for your draft
- [ ] **IBM Bob Usage Statement** — max 500 words, specific details on HOW Bob was used
  - Refer to `planning/BOB_USAGE_PLAN.md` for your draft
- [ ] **Technology & Category Tags** — include "IBM" and "IBM Bob 2.0"

### 💻 Application & Code
- [ ] **Public Code Repository URL** — must be publicly accessible
  - GitHub, GitLab, or Bitbucket
- [ ] **`bob_sessions/` folder** in the repo with:
  - [ ] Screenshots from **each team member**
  - [ ] All sessions related to the project solution
- [ ] **Demo Application Platform** — what platform is the demo hosted on?
- [ ] **Application URL** — live demo link (if applicable)

### 🎥 Video Demonstration
- [ ] MP4 format
- [ ] **Max 3 minutes** — judges will not watch beyond 3 minutes
- [ ] **At least 90 seconds** showing the solution in action on screen
- [ ] Brief intro to the problem (keep short — spend time on solution demo)
- [ ] Clearly shows IBM Bob being used in the workflow
- [ ] Includes narration explaining what is being demonstrated
- [ ] Uploaded to submission form

### 🖼 Media & Presentation
- [ ] **Cover Image** — uploaded to submission form
- [ ] **Slide Presentation** — uploaded to submission form
  - Should include: Problem, Solution, Bob usage, Demo highlights, Impact metrics

## 🚨 Common Disqualifying Mistakes

| Mistake | How to Avoid |
|---------|-------------|
| Repo is private | Set repo to Public; test in incognito browser |
| Missing `bob_sessions/` folder | Create folder early; add screenshots as you work |
| IBM Cloud credentials in repo | Use `.bobignore` and `.gitignore` templates |
| Video over 3 minutes | Edit tightly; judges stop watching at 3:00 |
| IBM Bob barely used | Bob must be the core engine — use Agent mode + subagents |
| Vague IBM Bob statement | Be specific: which feature, which task, what output |
| Missing team member screenshots | Each member must capture their own Bob session screenshots |
