TrustMeBro
Your agent keeps the roadmap.

Plan-first projects for AI coding agents: map the code, put every new task on the roadmap before touching it, keep the records current, and let the next session start where the last one stopped.

github.com/TonyLikeDev/tricklord1
The problem

Multi-session projects with an AI agent lose their thread.

Planning is manual. Turning an idea into phases, tasks, "done" criteria and risks takes days, and the plan ends up in scattered notes.

Every session starts cold. The developer re-explains where things stand, or the whole history is dumped into the context window.

We lived it

Our first IBM Bob planning session used ~160,000 tokens without writing a line of code, ~80,000 of them from fetching the same page twice.

TrustMeBro2
The solution

Three files the agent keeps current.

  1. Map it/layout-init writes LAYOUT.md: folders, components, database, where each piece of logic lives.
  2. Plan it/roadmap-planner turns an idea into PLAN.md, waits for approval, then creates ROADMAP.md.
  3. Record firstEvery new task goes on the roadmap before the code: feature, fix, or big work behind an approved plan.
  4. Tick with evidenceItems are ticked with the file, test or result that proves them; the layout is updated too.
  5. Resume coldThe next session starts from the progress headline and next actions, not from rereading the code.
TrustMeBro3
In IBM Bob

Copy .bob/ into a project. Bob does the rest.

  • Rules in .bob/rules/trustmebro.md, always loaded.
  • Hooks: SessionStart loads progress and next actions; UserPromptSubmit creates ROADMAP.md and reminds Bob: record first.
  • Skills: layout-init, roadmap-planner, roadmap-sync.

Live Bob Shell run: "Add multiply(a, b)"

Todo list step 1: add the task to ROADMAP.md. Roadmap entry before the code, then LAYOUT.md updated, item ticked with evidence, progress refreshed to 100%.

35 s · 12 tool calls · all checks passed
